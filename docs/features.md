## 0. 产品定位与全局约束

| 项 | 约定 |
|---|---|
| 纯本地 | 所有功能离线本地执行，无云端依赖、无账号、无遥测；唯一可选外联是用户自行配置的大模型 API（不配也能用，AI 相关功能置灰） |
| 双名机制 | 中文名「湛卢」、英文名「Zhanlu」；安装目录与进程名固定英文（`C:\Program Files\Zhanlu\`）；系统语言为中文时，界面/开始菜单/任务栏/托盘/文件关联提示均显示「湛卢」，非中文系统显示「Zhanlu」 |
| 界面语言 | 简体中文 + English，默认跟随系统，可手动切换，全量文案 i18n |
| 核心格式 | PDF、OFD；转换格式：Word(docx/doc)、Excel(xlsx)、PPT(pptx)、图片(png/jpg/webp/tiff，支持多张)、Markdown、TXT、HTML |
| 架构 | Tauri（桌面壳 + Web 前端）+ Python 本地处理引擎（sidecar 子进程，本地通信）；Windows 优先，平台专有代码（如 Office COM）集中隔离，预留跨平台 |

**优先级定义**：

- **P0** = 一期 MVP（覆盖全部核心需求）
- **P1** = 二期（完整对标 WPS 主体体验）
- **P2** = 三期（长尾增强）

## 二、分期总览

- **一期 P0（全部核心需求）**：PDF/OFD 阅读浏览、页面管理五件套、拆分/合并、全部 P0 转换（含 OFD 互转、Office→PDF、PDF→Word/Excel/PPT 基础版）、文本/表格/目录提取、AI 模型配置 + AI OCR + 可搜索 PDF、双名机制与中英文界面、设置中心、Office/LibreOffice 引擎接入。

- **三期 P2（长尾）**：受限文本编辑、表单/签名、翻译、贝茨、背景、托盘、更新检查等。

## 三、关键技术风险与预案

1. **OFD（最高风险）**：成熟开源实现几乎只有 Java 的 ofdrw。预案：自研轻量解析渲染（OFD = ZIP + XML，国标公开）先支撑「打开浏览 + OFD→PDF」；PDF→OFD 语义复杂，受阻则顺延 P1，或以插件形式内嵌 ofdrw（需带 JRE，体积 +100~150MB，仅作兜底选项）。
2. **PDF→Word/PPT 还原度**：本地算法有天花板。策略：基础还原 + AI 增强 + 图片模式三档，按文档质量让用户自选。
3. **许可证**：候选库 PyMuPDF 为 AGPL，个人自用无碍；若日后开源分发需同协议开源或购买商业许可，届时可切换 pikepdf/qpdf（宽松许可）组合规避。
4. **Office COM 仅 Windows**：符合「Windows 优先」；跨平台版自动禁用该引擎、回落 LibreOffice。
5. **AI OCR 质量依赖用户模型**：提供本地插件通道（M6.4）作为离线替代。
