# 湛卢 PDF · MVP 技术架构

本文件以 [首版产品定义](../product/mvp-v1/README.md)、[逐项验收](../product/mvp-v1/acceptance.md) 和 [Figma 32 幅界面索引](../design/mvp-v1/README.md) 为产品输入。范围是阅读、页面、转换、AI 四个模式。现有 v0.1 代码包含更广的实验功能；**设计覆盖已经补齐，运行能力仍须按下文的发布门槛逐项补齐**。目录归属以[目标结构](target-layout.md)为准，源码迁移属于下一阶段开发。

## 1. 核心决策

1. **文档会话与文件任务分开**：阅读中的页码、缩放、左侧导航和选区属于文档会话；切换阅读内工具时保留状态。首页快捷工具先选文件，合并与拆分创建独立任务会话，不加载阅读器。生成完成后，用户选择打开结果才创建文档标签。
2. **阅读留在前端工作线程**：React 管界面，pdf.js worker 解码和渲染 PDF。缩略图、文本索引和搜索结果增量生成，页面只保留视口附近的渲染结果。
3. **文件处理留在独立引擎**：Python 处理拆分、合并、页面操作、转换和 OCR；耗时工作进入任务队列。前端只通过文件 ID、页范围和任务 ID 与引擎交互。
4. **桌面壳拥有本机权限**：Tauri 负责原生文件选择、窗口、引擎子进程与会话密钥。WebView 不直接持有任意文件路径；浏览器开发模式通过上传副本登记文件。
5. **本地 AI 独立按需安装**：主安装包能阅读和整理 PDF。OCR/本地模型作为能力包运行于单独进程，失败不拖垮阅读器。远程模型是用户明确选择的另一个通道，不自动回退。
6. **输出不覆盖源文件**：页面、转换、OCR 先生成临时结果，校验后原子写入新文件并登记；任务失败时不留下看似完成的产物。

## 2. 仓库目录

```text
apps/
  desktop/                 Tauri 桌面宿主；窗口、文件授权、引擎生命周期
  web/                     Vite + React 前端源码
    src/
      app/                 应用入口、路由、文档会话和共享状态
      features/
        home/              最近文件与任务入口
        reader/            PDF 阅读
        pages/             拆分、合并与页面组织
        workflows/         首页进入的独立拆分、合并任务页
        convert/           格式转换
        ai/                AI 文档工作区与模型隐私确认
        settings/          本地能力与模型配置
        legacy/            首版导航外的历史功能
      shared/              API 传输、文件选择等跨功能基础件
      styles/              Figma 色彩令牌、布局和过渡样式
engine/
  zhanlu/
    core/                  PDF、转换、OCR/AI 等现有处理实现
    server.py              当前 HTTP 入口与路由；待按功能拆分
    tasks.py               当前后台任务；待持久化与取消
    store.py               文件登记簿；并发访问已加锁
  tests/
web/                       生成的前端资源；不手工编辑
docs/
  architecture/            当前架构与发布门槛
  design/                  Figma 对应规范、原型与历史探索
```

依赖方向：`app → features → shared`；功能模块之间通过应用层传递文件 ID 和任务意图，不直接互相读取内部状态。前端只能调用本机 API；API 调用 `core`，`core` 不依赖 HTTP、React 或 Tauri。Tauri 不实现 PDF 业务逻辑。

## 3. 运行与数据流

```text
原生选文件 / 浏览器上传
          ├─ 阅读 → 文档会话（文件 ID、页码、缩放）→ pdf.js
          └─ 首页合并 / 拆分 → 独立任务会话（文件顺序、页范围、名称、输出位置）
                                     ↓
                              本地 API → 任务队列 → PDF 引擎 → 新 PDF
                                     ↓
                              完成页 → 用户选择后打开阅读标签
```

每个任务记录输入文件 ID、操作参数、进度、取消状态、输出和错误。引擎只返回结果 ID；前端通过统一的任务队列展示进度和打开结果。AI 的检索片段必须保存来源文件 ID、页码和文字范围，回答引用可跳回原文。

当前浏览器实现先在应用输出目录生成结果；支持目录选择的浏览器可在任务完成后把结果复制到用户选定的文件夹，同时保留应用内登记。桌面版应由 Tauri 原生目录选择器授权输出位置，再让引擎写入选定目录；不要把任意输出路径直接交给未认证的本地 HTTP API。

多图转 PDF 的图片顺序由转换工作区的缩略图列表维护，删除仅从本次任务移除。点击生成时按当前列表顺序发送文件 ID；引擎按此顺序写入一个 PDF，并返回可登记、下载和打开阅读的结果 ID。前端预览页数等于列表中的图片张数。

## 4. API 与能力边界

| 领域 | 当前可复用 | MVP 尚需完成 |
| --- | --- | --- |
| 阅读 | PDF 原文与缩略图接口、pdf.js 单页/连续模式、近视口页面渲染、目录和全文搜索、文档标签；每文件页码、缩放和导航状态保存；复制本页文字与浏览器打印入口；加密 PDF 输入密码后可阅读 | 混合尺寸页面的精确滚动定位、1000 页性能验收、长文档缩略图虚拟化和增量索引、完整文字选区及加密文档的跨工具处理 |
| 页面 | `/api/pdf/split`、`/api/pdf/merge`、旋转/删除/移动；首页独立拆合任务页和结果入口 | 大文件预览性能、输出位置的桌面原生授权、异常页码和冲突文件名的完整处理 |
| 转换 | PDF 图片/文本等现有引擎与任务接口；多图转 PDF 按缩略图顺序提交并支持输出命名 | 只展示验收过的目标格式；能力包状态、取消和输出质量核对；桌面原生保存目录授权 |
| AI | 本地 Ollama 或远程模型配置；摘要、问答、粘贴文字解释/翻译接口；远程发送前确认；带来源页的回答可跳到阅读页 | 默认离线 OCR 与可搜索 PDF、本地模型安装与检测、阅读文字选区直达 AI、长文档摘要质量与引用核验 |
| 存储与任务 | 文件 ID 登记、内存任务队列；顶栏可查看进行中、完成和失败状态 | SQLite 事务、取消与重试、任务恢复、临时产物清理和安全输出 |

现有 OFD、表格提取、加密等实现放在历史能力中，首版导航不为它们单独增加模式。代码保留供后续验收，不作为首版完成度依据。

当前可运行的顶部文档操作菜单已收敛为阅读、整理页面、转换、AI 阅读，仅在打开 PDF 的阅读页出现；首页、任务、设置和功能搜索保留全局入口。阅读页进入任务会明确带入当前 PDF；从首页或功能搜索进入任务时需要选择文件，避免误用上次阅读的文档。AI 目前依赖用户自行连接模型，来源页是从送入模型的文本页中选择的参考页，不能代替逐句事实核验。现有 OCR 仅输出 TXT，尚未达到“离线可搜索 PDF”的发布标准。

## 5. 桌面发布门槛

下列事项来自 [现有架构评审](../architecture-review-2026-10-24.md)，完成前不应把当前本地服务包装成可分发的“安全离线桌面应用”：

1. **本地 API 访问控制**：由桌面壳启动时生成随机实例密钥；引擎校验 Host、Origin 和会话身份。禁止普通网页凭路径登记或读取任意本机文件。仅监听 `127.0.0.1` 不构成授权。
2. **受控 sidecar**：打包 Python 引擎及所需依赖；桌面壳选择端口、启动指定二进制并校验实例握手。不能扫描端口后复用任意已监听服务，也不能依赖仓库的 `.venv`。
3. **资源界限**：上传和原文下载改为流式；限制文件体积、缩略图 DPI 与并发；不可信文档解析在工作进程中隔离。
4. **凭据保存**：Windows 上远程模型密钥用当前用户的 DPAPI 加密后保存在本机配置；加密失败则拒绝保存新密钥。旧版异或/Base64 值仅为迁移兼容，重新保存时升级为 DPAPI。非 Windows 开发环境仍使用混淆，不计入 Windows 发布验收。
5. **任务与登记一致性**：文件登记簿并发读写已加锁；发布前迁入 SQLite，把结果登记与任务状态放在可恢复事务里，并支持取消。
6. **离线验收**：断网状态下完成阅读、拆合、基础转换、OCR 和本地问答；只有主动选择远程通道才允许发送内容。

## 6. 实施顺序

1. 以本次目录和色彩令牌为基线，把 Figma 的工作台外壳与四模式导航接入 `apps/web`，把旧的独立“提取”归入阅读或转换。
2. 建立文档会话与统一任务契约，先完成拆分/合并的预览与新文件输出。
3. 完成桌面文件授权、随机实例密钥、受控 sidecar 和 API 隔离。
4. 加入离线 OCR 与本地模型包，再完成有来源页的摘要、问答和翻译。
5. 用 [MVP 发布验收](../product/mvp-v1/acceptance.md) 和真实中文材料做跨进程、离线、长文档回归。
